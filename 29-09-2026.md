# Variables, Objects, and Memory Management in Python

**Date: 29-09-2026**

This guide explains what Python variables refer to, how assignment and mutability work, and how Python implementations manage object memory. The distinction between Python's language-level behavior and details specific to CPython is important throughout: the Python language defines what programs observe, while individual implementations can manage memory differently.

## 1. What is a variable in Python?

A variable is a name bound to an object. It is useful to think of the name as a label or reference, rather than as a box that permanently contains a value.

```python
score = 10
```

This statement creates or obtains the integer object `10` and binds the name `score` to it. Later, the name can be bound to a different object:

```python
score = 20
```

The second assignment does not change the integer object `10`. It changes which object the name `score` refers to.

Python names are created by binding operations such as assignment, function definitions, class definitions, and imports. A name must be bound in an accessible scope before it can be used; otherwise Python raises `NameError`.

## 2. Everything in Python is an object

In Python, values such as integers, strings, lists, functions, and classes are objects. Each object has:

- **Identity:** which particular object it is during its lifetime.
- **Type:** what kind of object it is and what operations it supports.
- **Value:** the data or state represented by the object.

For example:

```python
number = 10

print(id(number))   # An identity value for this object's lifetime
print(type(number)) # <class 'int'>
print(number)       # 10
```

`type()` reports an object's type, and evaluating the name gives access to its value. `id()` returns an identity that is unique among objects that exist at the same time. In CPython, an object's `id()` is commonly its memory address, but Python does not require this; code should not rely on identities being addresses or on a particular numeric identity.

## 3. Common built-in data types

Python provides built-in types for common kinds of values:

| Category | Common built-in types | Example |
| --- | --- | --- |
| Numeric | `int`, `float`, `complex` | `42`, `3.5`, `2 + 4j` |
| Boolean | `bool` | `True`, `False` |
| Text | `str` | `"hello"` |
| Sequences | `list`, `tuple`, `range` | `[1, 2]`, `(1, 2)`, `range(5)` |
| Sets | `set`, `frozenset` | `{1, 2}`, `frozenset({1, 2})` |
| Mapping | `dict` | `{"id": 101}` |
| Binary data | `bytes`, `bytearray`, `memoryview` | `b"abc"` |
| Absence of a value | `NoneType` | `None` |

The type determines which operations make sense. For example, a list can be changed in place, whereas a string cannot.

## 4. Numeric and Boolean values

Integers can be positive, negative, or zero. Python integers can grow beyond the fixed-width range used by many other languages, subject to available memory.

```python
age = 25
temperature_change = -10
```

Floating-point numbers represent approximate real numbers, so some decimal fractions cannot be represented exactly in binary floating-point.

```python
price = 99.9
percentage = 85.72
```

Complex numbers have real and imaginary parts. Python uses `j` for the imaginary unit:

```python
measurement = 3 + 4j
```

Boolean values are written with capital letters: `True` and `False`. Lowercase `true` and `false` are not Python boolean literals.

```python
is_active = True
is_logged_in = False
```

`bool()` converts a value to its truth value. Examples of values that are false in a Boolean context include `False`, numeric zero, `None`, and empty collections or strings. Most other values are true:

```python
print(bool(0))       # False
print(bool(1))       # True
print(bool(""))      # False
print(bool("hello")) # True
```

Truthiness is useful in conditions, but it does not mean that values such as `0`, `None`, and `""` are interchangeable. They remain different objects with different meanings.

## 5. Strings

A string (`str`) represents text. Strings are ordered sequences of Unicode code points and are immutable: an existing string cannot be modified in place.

```python
name = "Asiya"
print(name[0]) # A
print(name[1]) # s
```

An operation that appears to change a string creates a new string and binds a name to the result:

```python
greeting = "hello"
greeting = greeting + "!"
print(greeting) # hello!
```

The original string object was not edited; the name `greeting` was rebound to the result.

## 6. Lists

A list is an ordered, mutable collection. It allows duplicate values and can hold values of different types.

```python
data = [10, "python", 25.5, True]
numbers = [10, 20, 30]
```

Lists support positional indexing, starting at zero. Since lists are mutable, methods such as `append()` change the existing list object:

```python
numbers.append(40)
print(numbers) # [10, 20, 30, 40]
```

The list changes, but the objects stored as its elements are not necessarily changed. A list contains references to its elements; it does not generally contain independent copies of them.

## 7. Tuples

A tuple is an ordered sequence that cannot have its item bindings replaced, added, or removed after it is created. Tuples allow duplicates.

```python
point = (10, 20)
```

Tuple immutability is shallow. If a tuple contains a mutable object, that object can still be changed:

```python
items = ([1, 2], "fixed")
items[0].append(3)
print(items) # ([1, 2, 3], 'fixed')
```

The tuple still refers to the same list, but the list's contents changed.

## 8. Sets

A set is a mutable collection of distinct, hashable elements. It does not provide positional indexing, and its iteration order should not be used as a substitute for a list's positional order.

```python
numbers = {10, 20, 30, 30}
print(numbers) # Contains 10, 20, and 30; duplicates are removed
```

An immutable set is a `frozenset`:

```python
fixed_numbers = frozenset({10, 20, 30})
```

## 9. Dictionaries

A dictionary (`dict`) stores key-value pairs. Keys must be hashable, and assigning a value to an existing key replaces that key's previous value.

```python
student = {
    "id": 101,
    "name": "Sandhya",
    "marks": 85,
}

print(student["name"]) # Sandhya
student["marks"] = 90
```

Dictionaries preserve insertion order in modern Python. They are mutable, and their values may be objects of different types.

## 10. `None`

`None` is Python's single value representing the absence of a value or a deliberate lack of a result. Its type is `NoneType`.

```python
result = None
```

`None` is different from `0`, `False`, an empty string (`""`), and an empty list (`[]`). Although several of these values are false in a condition, they communicate different things. To test specifically for `None`, use identity comparison:

```python
if result is None:
    print("No result is available")
```

## 11. Mutable and immutable objects

An **immutable** object cannot be changed after it is created. Operations that seem to modify one produce another object or another value instead. Common immutable built-in types include `int`, `float`, `complex`, `bool`, `str`, `bytes`, and `tuple` (with the shallow-immutability detail described above). `frozenset` is also immutable.

A **mutable** object can have its state changed while remaining the same object. Common mutable built-in types include `list`, `dict`, `set`, and `bytearray`.

```python
text = "cat"
text = text + "s"  # A new string is produced; text is rebound

items = ["cat"]
items.append("dog") # The existing list is changed
```

Mutability is a property of the object, not of the variable name. A name can be rebound regardless of whether its current object is mutable or immutable.

## 12. Assignment, rebinding, and aliasing

Assignment binds a name to an object. Assigning one name to another does not automatically copy the object:

```python
a = 10
b = a
```

Both names refer to the integer value `10`. If `a` is later assigned a different value, only the binding of `a` changes:

```python
a = 20
print(a) # 20
print(b) # 10
```

Integers are immutable, and `a = 20` rebinds `a`; it does not modify the integer object previously referenced by `a` or change `b`.

With a mutable object, two names can be aliases: different names for the same object.

```python
a = [10, 20]
b = a
b.append(30)

print(a) # [10, 20, 30]
print(b) # [10, 20, 30]
```

`a` and `b` refer to the same list, so a mutation made through either name is visible through the other. Rebinding one name is different from mutating the shared object:

```python
b = [99]
print(a) # [10, 20, 30]
print(b) # [99]
```

Now `b` refers to a different list, while `a` still refers to the original list.

If an independent shallow copy of a list is needed, use an operation such as `a.copy()` or `a[:]`. A shallow copy creates a new outer list, but its elements are still references to the same element objects. Nested mutable structures may require a deliberate deep-copy strategy.

## 13. `==` compared with `is`

The `==` operator asks whether two objects compare equal in value. The `is` operator asks whether two references identify the very same object.

```python
a = [1, 2]
b = [1, 2]

print(a == b) # True: the lists have equal contents
print(a is b) # False: they are distinct list objects
```

If two names are bound to the same object, both comparisons are true for ordinary built-in values:

```python
first = [1, 2]
second = first

print(first == second) # True
print(first is second) # True
```

Use `is None` or `is not None` when testing for `None`. Do not generally use `is` to compare numbers, strings, or other values: implementation optimizations such as object reuse are not a substitute for value equality.

## 14. Where does Python use memory?

While a Python program runs, memory is used for many things, including objects representing numbers, strings, lists, dictionaries, functions, classes, and application data. The implementation also needs memory for interpreter state and other runtime bookkeeping.

At the Python language level, programs work with objects and references, not with specified physical addresses. The language does not promise that a particular object is stored at a particular address or that each source-level variable corresponds to a dedicated physical memory slot.

In CPython, objects are managed by Python's memory-management system, which obtains memory from the process and uses implementation-specific allocation mechanisms. Other Python implementations can make different choices. Therefore, descriptions of exact object layout or allocation are implementation details, not universal Python guarantees.

## 15. Reference counting in CPython

CPython uses reference counting as an important part of its memory management. Conceptually, an object remains referenced while names, containers, or other runtime structures hold references to it. Creating or removing references changes how many references the implementation tracks.

```python
first = [1, 2, 3]
second = first
```

Both names refer to the same list. Removing one binding does not remove the other:

```python
del second
print(first) # [1, 2, 3]
```

The example illustrates the references, not an exact count. The interpreter can hold internal references as well, and the details of reference counting are specific to the implementation. Python code should not depend on a particular reference count.

## 16. Garbage collection and reference cycles

Garbage collection is the process of finding objects that are no longer needed and making their memory available for reuse. Python manages object memory automatically; ordinary Python code does not call `free()` to release an object.

Reference counting alone cannot reclaim a group of objects that refer to one another, even if nothing outside the group can reach them. Such a group is a **reference cycle**:

```python
items = []
items.append(items) # The list contains a reference to itself
```

CPython includes a cyclic garbage collector that can detect and reclaim unreachable cycles. The `gc` module exposes controls and diagnostics for this collector, but most application code does not need to manage it directly. Other Python implementations may use different garbage-collection strategies.

## 17. What does `del` do?

The `del` statement removes a name binding, an item, or an attribute, depending on how it is used. It does not mean “immediately destroy this object.”

```python
numbers = [1, 2, 3]
another_name = numbers

del numbers
print(another_name) # [1, 2, 3]
```

The list remains accessible through `another_name`. `del numbers` removed the name `numbers`, not the list itself.

When no live references can reach an object, the object may become eligible for reclamation. Even then, Python does not promise exactly when reclamation occurs or when memory is returned to the operating system. The memory manager may retain reclaimed memory for reuse by the process.

## 18. When can an object become garbage?

An object is generally reclaimable when it is no longer reachable by the running program. For example, after all bindings to a list are removed and no other object retains it, the program can no longer use that list through those bindings:

```python
numbers = [1, 2, 3]
alias = numbers

del numbers
del alias
```

In this simple example, neither name refers to the list after both `del` statements. If a different container, global variable, closure, or other live object still refers to it, it remains reachable. Cycles require cycle-aware collection when reference counting alone cannot reclaim them.

“Eligible for reclamation” does not mean that memory has immediately been returned to the operating system. Object lifetime, reuse of memory inside the Python process, and returning memory to the operating system are separate events.

## 19. A compact model to remember

For everyday reasoning, this model is useful:

```text
name (variable) -> object (identity, type, value)
                         |
                  managed by Python
                         |
        unreachable objects may be reclaimed
```

Names refer to objects. Assignment can create another binding to an existing object or rebind a name. Mutating a mutable object changes that object; rebinding a name does not. Python manages object memory automatically, but the timing and mechanics of reclamation depend on the implementation.

## 20. If Python has garbage collection, why does `del numbers` not necessarily destroy an object immediately?

Because `del numbers` removes the binding named `numbers`; it does not directly command the runtime to destroy the object. Another name or object may still refer to it, in which case it is still reachable and must remain usable. Even after an object becomes unreachable, the implementation decides when to reclaim it. CPython often reclaims non-cyclic objects promptly through reference counting, while cycles may require the cyclic garbage collector. Memory that has been reclaimed may also be kept by the Python memory manager for reuse instead of being returned immediately to the operating system.

The practical rule is: use `del` to remove a name or item when that is what your program needs, not as a guarantee of immediate memory release.
